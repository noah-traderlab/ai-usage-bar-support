# 古い読込結果を表示へ戻さない：AI Usage Barの防御保守事例

2026年11月17日。対象はWindows候補版 **0.1.1-rc.1**。保守主体は
[@noah-traderlab](https://github.com/noah-traderlab) です。調査、実装、テスト、
文書と別担当によるレビューにAIエージェントを使用しています。
人間の第三者による監査、外部での採用、CVEを示す事例ではありません。

## 問題と修正

チーム管理画面では、設定変更や再読込の前に取得した結果が後から返ることが
あります。古い成功結果やエラーをそのまま表示へ適用すると、新しい読込の状態を
上書きしてしまいます。また、読込失敗時に以前の集計が残ると、利用者には
現在も有効な集計であるように見えてしまいます。

修正では、読込開始時に前の表示・キャッシュを消去し、各要求に世代番号を
付けています。結果を適用できるのは現在の世代だけです。画面を閉じた後の結果も
適用しません。`TeamRefreshGate` はこの世代判定を担う小さな本番処理です。
UIスレッド上で呼ぶ設計であり、複数スレッド間の排他制御を提供するものではありません。

同じ修正版には端末の明示承認と集計先の固定も含まれますが、この公開キットが
直接検証する対象は **読込世代管理だけ** です。端末認証や署名付き報告の
送受信を検証したという意味ではありません。

## 観測と、読者が検算できる範囲

開発時には、合成データを持つ非表示の実フォームで同じ同期読込失敗を比較しました。
修正前は表示120トークン・キャッシュ1件、修正後は表示0・キャッシュ0件でした。
これは保守側の観測記録です。この公開キットから当時の非公開開発環境や
修正前フォームを再構成できるという主張ではありません。

今回公開する検証コードは、コピーした修正アルゴリズムをテストするのではなく、
[公開ZIP](https://github.com/noah-traderlab/ai-usage-bar-support/releases/tag/windows-v0.1.1-rc.1)
内の本番アプリに含まれる `TeamRefreshGate` を直接呼びます。
固定したZIP・setup・埋込本体のSHA-256が一致した場合だけ、架空の表示状態と
コールバックを渡します。インストーラーとアプリのエントリーポイントは呼びません。
手順、実コード、期待結果と記録は[キットのREADME](README.md)から確認できます。

検証対象は、読込開始による合成状態の消去、旧要求の成功・エラーの拒否、
現在の要求の適用、終了後の要求の拒否です。実画面のイベントループ、認可全体、
実ユーザー環境、通信、署名付き報告、Mac互換性は対象外です。
ハッシュは同じバイト列の確認であり、安全性や作者本人性の保証ではありません。

## 既存の検証との関係

- 開発時の承認・UIの限定検証は64件でした。このキットの件数とは別です。
- 同じ候補ZIPの隔離Windows Server 2025での導入・更新・設定保持・終了・解除は
  成功しています。144チェックには環境・ハッシュ等の確認も含まれます。
- 上記の範囲と未確認事項は[日付付き公開追補](../../WINDOWS-0.1.1-rc.1-VERIFICATION.md)
  に記録されています。Windows 10/11の通常利用、非管理者、SmartScreen、手動UIを
  すべて確認済みとするものではありません。
